# AI写的代码，合并前过这5关

适合：开发者与技术写作者。
把差一点才正确，拆成可以逐项检查的交付问题。

```mermaid
mindmap
  root((AI写的代码，合并前过这5关))
    需求关
      先还原任务
        用户触发什么行为
        预期结果是什么
      控制修改范围
        有没有顺手改无关代码
        接口是否仍兼容
    行为关
      走通一条真实路径
        正常输入得到什么
        结果能否被独立核对
      补上边界样本
        空值与重复操作
          例：用户重复提交表单
            先观察实际写入次数
            再核对重复处理策略
              UI提示不能代替状态验证
        超长输入与失败重试
    权限关
      数据从哪里进入
        不信任外部输入
        核对访问与写入边界
      检查敏感信息
        日志不带密钥
        依赖来源需要确认
    失败关
      让异常可理解
        失败是否明确返回
        是否保留恢复入口
      测试关键后果
        验证真实状态变化
        不要只验证函数被调用
    维护关
      未来的我看得懂吗
        名字能说明意图
        复杂分支有必要吗
      准备可审查的交付
        写明改了什么与为什么
        记录通过和未验证的检查
```

这是Mindbox编辑的实践范例，不是效果承诺；时间安排与检查项可按实际情况修改。
